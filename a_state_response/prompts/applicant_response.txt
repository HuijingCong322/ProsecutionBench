Propose the reply the applicant should file. Use only the supplied record. Do not claim that an argument will

Return ONE JSON object with exactly these keys:

strategies: every strategy the reply uses, from exactly these four labels:
  amendment      the reply changes the claims (amends or adds claims), the specification or the drawings
  argument       the reply presents remarks/arguments against at least one rejection or objection
  cancellation   the reply cancels at least one claim
  other          anything else filed with the reply: terminal disclaimer, declaration/affidavit (37 CFR 1.130-1.132),
                 interview request or interview summary
If the reply changes no claim, "edits" is an empty list.

edits: one entry per claim you change; unchanged claims are not listed. Use the numbers of the claims currently
under examination; new claims take the next unused numbers. new_text is the complete claim including its preamble
and dependency ("The method of claim 1, ..."). Amendments must be supported by the specification as filed.

resulting_proposed_claims: the complete claim listing as it would be filed with the reply (every claim number,
including withdrawn and previously canceled claims), with the status label each claim would carry.

arguments: split the remarks into argument units, one independent assertion each, linked to the claims and the
rejection it answers. support_span must be copied verbatim from support_doc_id (specification, claims, the Office
action, or another record document); do not paraphrase inside support_span. If the record does not contain support
for an assertion, set support_doc_id to "insufficient_evidence" rather than inventing a citation.

Return only the JSON object.
